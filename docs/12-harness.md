# 하네스 — 테스트 · 린트 · 커밋 전 리뷰

작성: 2026-08-17
범위: 레포 전체 (`app/` + `bench/` + `.claude/hooks/`)

```bash
.venv/bin/python -m pytest        # 139개 · 0.8초 · 브라우저도 서버도 필요 없다
.venv/bin/ruff check .            # 린트

```

## 1. 이 하네스가 무엇을 막으려 하는가

이 레포의 사고는 **거의 다 예외 없이** 일어났다.

| 사고 | 겉으로 보인 것 | 실제 |
|---|---|---|
| WEBP 전송 | HTTP 200, 정상 JSON | 모델이 이미지를 못 봤고 답은 환각이었다 |
| system turn 오염 | 아무 일 없음 | 프리픽스 캐시 사망. 그냥 느려졌다 |
| 덜 그려진 프레임 | 로그 깨끗 | 탐색이 다른 길로 샜다 |
| 경도 격자 미끄러짐 | 정상 동작 | 재방문 감지가 영영 안 걸렸다 |
| Metal OOM 좀비 | `/health` 200 | 서버는 죽어 있었다 |

그래서 **"예외가 안 났다" 는 아무것도 보장하지 않는다.** 테스트는 전부
불변식으로 걸려 있고, 각 파일 맨 위에 어느 사고에서 나왔는지 적혀 있다.

## 2. 테스트

`app/tests/` · 139개 · 0.8초. **브라우저도 VLM 서버도 띄우지 않는다.**

| 파일 | 지키는 것 |
|---|---|
| `test_prompt.py` | 해시 핀 · 버전 선택 · 스키마 필드가 프롬프트에 정의돼 있는가 |
| `test_imaging.py` | 무엇을 넣어도 JPEG · 고정 크기 · 늘리지 않고 자른다 |
| `test_vlm.py` | 조용한 실패 감지 (이미지 무시 · 캐시 미스 · 500 연속 · 잘린 출력) |
| `test_walk.py` | 온 길 제외 · 막다른 길이 폴백으로 새지 않음 · frontier |
| `test_kakao_settle.py` | 프레임 안정화 (이 레포에서 가장 비싸게 배운 버그) |
| `test_geo_providers.py` | 측지 왕복 · 격자 스냅 안정성 |
| `test_config_secrets.py` | 키 값이 예외·진단 출력 어디에도 안 나온다 |

### 브라우저·서버가 필요한 것은 일부러 뺐다

유닛 테스트로 흉내내면 느리고 잘 깨지는데 정작 진짜 문제는 못 잡는다.
그쪽은 각자의 도구가 있다:

- `app/check_kakao.py` — 키·도메인·커버리지·렌더를 갈라서 진단
- `app/run_walk.py --provider fixture` — VLM 서버까지 포함한 전체 배선
- 실제 walk 런 — 판정 품질. 이건 자동화할 수 없고 사람이 캡처를 봐야 한다

### 판정 품질은 테스트하지 않는다

`test_walk.py` 가 보는 것은 판정을 받은 **뒤의 행동**이다. "이 사진이 산책로인가"
가 맞았는지는 프롬프트 문제이고 `app/docs/23-open-questions.md` §5 의 영역이다.
둘을 섞으면 둘 다 못 잰다.

### 가짜 페이지로 브라우저 코드를 검증한다

`kakao.py` 의 `_settle`/`_await_tiles` 는 페이지 객체의 아주 좁은 인터페이스만
쓴다(`locator().screenshot()`, `wait_for_timeout()`). 그래서 `__init__` 을
건너뛰고 가짜 페이지를 꽂으면 Playwright 없이 프레임 시퀀스를 정확히 재현할 수
있다. **1차 수정이 뚫렸던 `A,A,B,B,B` 시퀀스가 테스트로 굳어 있다.**

## 3. 린트

ruff. `E W F I B UP SIM RUF`.

의도적으로 끈 것들과 그 이유는 `pyproject.toml` 에 주석으로 붙어 있다.
핵심은 **E702**(한 줄 세미콜론)다 — `res.stop_reason = "dead_end"; break` 는
종료 이유를 탈출문 옆에 붙여 두는 관용구이고, 두 줄로 풀면 `walk.py` 의 종료
조건이 눈으로 안 잡힌다.

> 린트는 울릴 때 진짜여야 쓸모가 있다. 안 그러면 사람이 규칙째로 무시한다.
> 이 레포는 같은 교훈을 훅에서 이미 한 번 배웠다 (§4).

`bench/sweep.py` 의 `SYSTEM` 문자열에는 `# noqa: E501` 이 붙어 있다.
**바이트가 고정이어야 하는 벤치 픽스처**라 줄바꿈을 옮기면 문자열이 바뀌고
예전 수치와의 비교가 끊긴다. 여기서는 재배치가 곧 데이터 손상이다.

## 4. 커밋 전 리뷰 훅

`.claude/hooks/review-on-commit.py` · PreToolUse(Bash) · 타임아웃 300초.

```
git commit
   │
   ├─ git commit 이 아니면            → 즉시 통과 (거의 모든 Bash 호출)
   ├─ --no-verify 가 있으면           → 통과
   ├─ 리뷰 에이전트 안에서 온 것이면   → 통과 (재귀 차단)
   │
   ├─ 1단계  ruff + pytest           → 실패하면 **차단**
   │
   └─ 2단계  claude -p 리뷰 에이전트  → 스테이지된 diff 만, 읽기 전용
                ├─ blocking          → **차단**
                └─ advisory          → 통과시키되 본문에 붙여 보여준다
```

### 왜 두 단계인가

1단계는 **사실**이다. 깨진 테스트를 커밋할 이유가 없으니 무조건 막는다.
2단계는 **판단**이다. 판단으로 사람을 막을 때는 조심해야 한다.

### 과잉 차단은 훅을 죽인다

이 레포는 이 교훈을 이미 한 번 치렀다. `block-secret-reads.py` 의 첫 판은
`.env` 를 **언급**만 해도 막아서 커밋 메시지조차 못 쓰게 만들었다.
그런 훅은 곧 꺼지고, **꺼진 훅은 아무것도 막지 못한다.**

그래서 리뷰 단계는 이렇게 설계했다:

- **리뷰어가 고장나면 통과시킨다.** `claude` 가 없거나, 타임아웃이거나, JSON 이
  깨졌으면 커밋을 막지 않고 "리뷰가 안 돌았다" 는 사실만 알린다.
  리뷰 인프라 장애로 커밋이 막히면 사람이 훅부터 지운다
- **차단은 `blocking` 에만.** 스타일·취향은 절대 차단하지 않는다 (ruff 가 이미 돌았다)
- **`--no-verify` 는 언제나 존중한다.** 탈출구 없는 게이트는 게이트가 아니다
- diff 가 120KB 를 넘으면 에이전트 리뷰를 건너뛴다

### 리뷰어에게 무엇을 시키는가

프롬프트에 이 프로젝트의 **위험 성격**을 먼저 알려준다. 일반적인 코드 리뷰가
아니라 조용한 실패를 찾게 한다:

1. 조용한 실패 — 예외 없이 틀린 결과가 나오는 경로
2. 비밀값 누출 — 키가 로그·예외·URL 에 들어가는가
3. 재현성 파괴
4. 명백한 버그
5. 문서와 코드의 어긋남

`--permission-mode plan` + `--allowedTools Read Grep Glob` 으로 **쓰기를 막는다.**
리뷰어가 코드를 고치기 시작하면 그건 리뷰가 아니다.

### 실제로 잡는가 — 검증

일부러 심은 결함으로 확인했다. 네트워크 오류를 `False` 로 뭉개는 코드:

```python
except Exception:
    out.append(False)        # 실패와 "산책로 아님" 이 구분되지 않는다
```

리뷰어 판정:

> `[blocking]` bare except 가 네트워크 오류·HTTP 오류·JSON 파싱 실패·KeyError 를
> 모두 False 하나로 뭉갠다 → 서버가 500 을 반환해도 예외가 삼켜지고 호출자가
> 실패와 정상 부정 판정을 구분할 수 없다

이 레포에서 가장 비싼 버그 유형을 정확히 짚었다.

### 다른 훅

| 훅 | 하는 일 |
|---|---|
| `block-secret-reads.py` | `.env` 직접 읽기 차단. 자체 테스트 24개 (`test-block-secret-reads.sh`) |
| `keycheck.py` | 어떤 키가 있는지 **값 없이** 확인 (이름·길이·sha256 앞 8자) |

## 5. 알려진 한계

- **판정 품질에 대한 회귀 테스트가 없다.** 정답이 눈으로 확인한 7건뿐이다.
  코스 폴리라인(`app/docs/23-open-questions.md` §4)이 풀려야 생긴다
- **CI 가 없다.** 지금은 커밋 훅이 유일한 게이트라 `--no-verify` 로 그냥 지나간다
- **리뷰 에이전트는 비결정적이다.** 같은 diff 에 매번 같은 지적이 나오지 않는다.
  1단계(ruff/pytest)와 성격이 다르며, 그래서 차단 범위를 좁게 잡았다
- `equirect_to_view` 는 테스트는 있지만 **실제 파노라마로 검증된 적이 없다**

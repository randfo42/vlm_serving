# 문서 색인 — 애플리케이션 (trailwalk)

로드뷰를 따라 걸으며 산책로를 식별하는 클라이언트.
**이미지 1장에 대한 판정**은 이 레포의 서빙 쪽(`../../docs/`)이 하고,
**어디로 갈지·어떻게 이어갈지**를 여기가 한다.

번호를 20번대로 둔 이유: 서빙 문서가 00번대·10번대를 쓰고 있어 겹치지 않게 하기 위해서다.

## 현재 상태 (2026-08-24)

### 배선·판정

- ✅ 배선 완료. fixture provider 로 end-to-end 검증 (API 키 없이 전 경로)
- ✅ 프롬프트를 서빙 → 애플리케이션으로 이관. 파일 + 해시 핀
- 🟡 **판정의 축이 두 번 바뀌었다.** v1~v4 는 **노면**을 물었고(카메라가
  무엇 위에 있는가 · 차와 공유하는가), v5 부터는 **주변 자연**을 묻는다.
  v4 를 버린 이유는 약수역 1km 런에서 `park_path` 2건 중 하나가 **터널 안
  차도**였기 때문이다 — 노면만 보면 터널 바닥과 공원 길이 둘 다 회색 면이다
- 🟡 **v6 은 응답이 둘이다** — `nature_level`(0~3) + `footway`(0/1).
  한 필드에 두 뜻을 섞으면 낮은 판정이 "자연이 없다" 인지 "걸을 데가 없다"
  인지 구별할 수 없다
- 🟡 **경계는 전부 가설이다** — `min_nature_level`(2)과 `require_footway`(true)
  는 라벨 세트가 서야 정해진다. 둘 다 설정이라 **재판정 없이** 옮길 수 있고,
  그게 런로그에 원본 값을 다 남기는 이유다 (`23-open-questions.md` §5)
- ✅ **판정은 진행축 한 장이면 된다** — 정반대 방위 19쌍이 100% 일치. 반대로
  여러 화각 다수결은 12건 전부 정답을 뒤집는다 (`23-open-questions.md` §6)
- ✅ 비밀값 취급 정리. `app/.env` + 읽기 차단 훅 + 값 없는 점검 창구 (`20-app-design.md` §9)

### 로드뷰

- ✅ **Kakao 로드뷰 실제 주행 성공** — 청계천 20스텝 229m, 판정도 맞았다
  (차도 거부 → 하천 보행로 추적). 커버리지 4/5 표본 확인 (`20-app-design.md` §6.1)
- ✅ **이웃 pano 그래프 확보** — 화면의 흰 화살표가 SDK 의 JSON 에 데이터로 있었다.
  좌표 밀기 → 그래프 순회로 전환 (`21-roadview-providers.md` §1.3)
- ✅ **캡처 재현성 확보** — 타일 로딩 완료 + 연속 3프레임 + 세션 첫 캡처 폐기.
  같은 시작점 런 두 번이 probe 24개까지 일치 (`20-app-design.md` §5)
- ✅ **화각 측정 완료** — `zoom 0` = 가로 90.9° / 세로 59.5° (`23-open-questions.md` §3)
- ✅ **`shot_tool` 로 차량/도보를 가른다** — 카카오 자신의 판정 규칙이 뷰어 번들에
  있었다. 차량은 `{102, 200, 202}` 세 개뿐 (`21-roadview-providers.md` §1.3b)
- ✅ 진단 도구 `check_kakao.py` / `check_fov.py` — VLM 없이 돈다

### 탐색 루프

- ✅ **explore(BFS) 하나로 합쳤다 (2026-08-20).** 한 길만 따라가던 walk 를 지웠다 —
  갈림길에서 나머지를 frontier 에 기록만 하던 루프라 explore 의 부분집합이었다
  (`20-app-design.md` §3)
- ✅ **예산은 시간과 시작점 반경 둘이다 (2026-08-20).** 호출 수·걸음 수·"아님"
  인내 횟수를 전부 걷어냈다. 사용자가 정하는 것은 반경이다
- ✅ **이동을 그래프 하나로 정리** — 좌표 밀기 폴백 · `side_offsets` ·
  `start_offsets` · `geo.destination` · 재방문 감지를 전부 없앴다
- ✅ **시작점은 화살표를 전부 본다** — 진행 방위가 갈래를 지우던 버그를 고쳤다
- ✅ **결과를 지도 위에서 본다** — `run.dump` JSON → `eval/plot_explore.py` 가
  OSM 타일을 깐 SVG 한 장
- ✅ **경고 채널 (2026-08-20)** — `warnings[]` 로 "이 결과를 믿어도 되나" 를
  따로 답한다. 캡처 실패·이웃 로드 실패·캐시 미스가 여기로 모이고, 런이
  성립하지 않았으면 stderr + exit 2 다 (`20-app-design.md` §3)

### 라벨·평가

- ✅ **코스 폴리라인 확보 (2026-08-19)** — 경유지 지오코딩 + 카카오 도보 길찾기.
  종로 9코스 · 서울 89코스 (`22-labels.md` §7, `24-course-routes.md`)
- ✅ **라벨 세트** — 종로 335건 · 서울 914건. 전부 코스 폴리라인 위 pano 다
- ✅ **평가 파이프라인** — `run_eval.py` → `eval/report_eval.py`
- 🔴 **지금 세트는 양성 전용이다.** 재현율만 나오고 precision·FPR·ROC 는
  정의되지 않는다. 전역 오탐률을 보려면 "아예 산책로가 아닌 곳" 수집이 와야
  한다 (`22-labels.md` §4, §5)
- 🔴 **검수가 아직 안 됐다.** 자동 라벨은 검수 전 가설이고, `labels.jsonl` 의
  `flipped` 가 0 이다 — 문서가 눈으로 확인했다고 적은 차도 장면 재분류가
  파일에 없다 (`22-labels.md` §8)

### 남은 것

- 🔴 **이미지 저장 약관** — Kakao 에 공식 문의 미실시. 배포·공개·대량수집 전 필수
  (`23-open-questions.md` §2). 기본은 저장 끄기(`run.save_images: false`)
- 🟡 **차량 촬영과 도보 촬영 pano 계열이 그래프로 안 이어져 있다.** 차도에서
  시작하면 보행로에 못 내려간다 — 웹 UI 의 시작점 처리가 풀어야 한다
  (`23-open-questions.md` §7)
- ⬜ `confidence` 변별력 미검증. 다만 `walk`/`eval` **스키마**가 판정을 바꾸지
  않는다는 것은 확인했다 (8/8 일치) — 평가 정확도를 루프 정확도로 읽어도 된다
- ⬜ 형태 2(경로 커버리지) 평가 — 서울시가 정한 코스 선이 필요하다
  (스마트서울맵, 페이로드 형식 미상)

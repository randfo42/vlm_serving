# 문서 색인 — 애플리케이션 (trailwalk)

로드뷰를 따라 걸으며 산책로를 식별하는 클라이언트.
**이미지 1장에 대한 판정**은 이 레포의 서빙 쪽(`../../docs/`)이 하고,
**어디로 갈지·어떻게 이어갈지**를 여기가 한다.

번호를 20번대로 둔 이유: 서빙 문서가 00~11번을 쓰고 있어 겹치지 않게 하기 위해서다.

---

## 읽는 순서

### 처음이라면
→ **`../README.md`** — 빠른 시작. fixture 로 5분 안에 한 바퀴 돌려볼 수 있다

### 설계를 이해하려면
1. **`20-app-design.md`** — 경계, 한 스텝의 모양, 프롬프트 소유권, 실측
2. **`21-roadview-providers.md`** — Kakao/Naver/Google 조사. **왜 브라우저를 모는가**
3. `22-labels.md` — 정답 데이터. 무엇을 얻었고 무엇이 없는가
4. **`23-open-questions.md`** — 지금 막혀 있는 것

- ✅ 프롬프트를 서빙 → 애플리케이션으로 이관. 파일 + 해시 핀
- ✅ 레이블 150건 수집 (`labels/trails.json`)
- ✅ 비밀값 취급 정리. `app/.env` + 읽기 차단 훅 + 값 없는 점검 창구 (`20-app-design.md` §9)
- ✅ **Kakao 로드뷰 실제 주행 성공** — 청계천 20스텝 229m, 판정도 맞았다
  (차도 거부 → 하천 보행로 추적). 산책로 커버리지 4/5 표본 확인 (`20-app-design.md` §6.1)
- ✅ 진단 도구 `check_kakao.py` — 키/도메인·커버리지·렌더 실패를 갈라준다
- ✅ **이웃 pano 그래프 확보** — 화면의 흰 화살표가 SDK 의 JSON 에 데이터로 있었다.
  좌표 밀기 → 그래프 순회로 전환 (`21-roadview-providers.md` §1.3, `20-app-design.md` §3)
- ✅ **판정 기준 확정** — "카메라가 산책로 위에 있는가" (`system_v3`).
  같은 이미지 24장 재판정에서 눈으로 확인한 7건을 전부 맞혔다 (v1 은 5, v2 는 4).
  `--prompt` 로 버전을 고를 수 있다 (`23-open-questions.md` §5)
- ✅ **캡처 재현성 확보** — 타일 로딩 완료 + 연속 3프레임 + 세션 첫 캡처 폐기.
  같은 시작점 walk 두 번이 probe 24개까지 일치 (`20-app-design.md` §5)
- 🔴 **코스 폴리라인이 없어 정량 평가 불가** — 이제 이게 유일한 평가 블로커다
  (`22-labels.md` §2). 지금 정답은 눈으로 확인한 7건뿐이다
- ✅ **하네스 구축** — pytest 139개(0.8초) · ruff · 커밋 전 리뷰 훅.
  테스트는 전부 실제로 났던 사고에서 나왔다 (`../../docs/12-harness.md`)
- ⬜ `confidence` 변별력 미검증. 다만 `walk`/`eval` 스키마가 판정을 바꾸지
  않는다는 것은 확인했다 (8/8 일치) — 평가 정확도를 루프 정확도로 읽어도 된다
